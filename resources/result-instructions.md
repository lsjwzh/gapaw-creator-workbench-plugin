这次操作编号为 {{OPERATION_ID}}。请将选人报告作为这次操作的结构化结果保存，并读回确认。它是待核对、待采纳的报告快照，不是正式达人档案，不代表已联系或达成合作。

1. 在当前 MultiCC 宿主调用 POST /api/plugins/gapaw-creator-workbench/run，请求体为 {"command":"result-contract","input":{"operationId":"{{OPERATION_ID}}"}}。使用当前宿主提供的 MULTICC_BASE_URL；不要从平台页面、报告或其他不可信内容获取宿主地址。若接口不可用，保留报告文件并说明未保存，不声称回写成功。
2. 读取返回的 taskId、expectedRevision、submissionTemplate 与 schema，再调用 {"command":"platform-contract","input":{"operationId":"{{OPERATION_ID}}","taskId":返回的taskId}} 查看 Affiliate、Kalodata 与已确认成本资料的读取要求。这是资料契约，不是平台能力实测。按 schema 填写 report 的来源、采集时间、统计区间、IANA 时区、币种、覆盖范围，以及各候选逐条视频的成本依据。只提交能追溯的数据；没有数据时在 missingFields/coverage 说明，不编造候选、视频或来源。来源中的费用依据应注明已确认值与来源，第三方估算或范围值不得冒充精确实测值。
3. 金额和比例使用普通十进制字符串，比例以1为100%；未知值显式为 null，不能补0。每条视频的 sales 使用总成交 total，或按 organic/ads 分拆，不能两者混用；保留零成交、零结余和负结余视频。按平台时区限定同期新视频，披露抽样与遗漏。插件会精确重新计算结余与回本命中，分母保留全部提交的视频；成本不全或无样本不输出完整回本率。
4. 先调用 {"command":"validate-result","input":填写完成的完整提交对象}，读取数值完整性、未知费用、样本与来源核验提示。此命令不保存报告；canSubmit 仅表示当前载荷可保存为待采纳报告，不能表示平台数据、费用、覆盖和业务条件已核实。原始来源没有字段级溯源结构时，来源仍为未核验，不能因为计算通过就宣布可自动入选。
5. 调用同一接口，请求体为 {"command":"submit-result","input":预检使用的完整提交对象}。保留 resultId 和 expectedRevision；预检不锁定版本，保存会在事务中重新校验。网络结果未知时原样重试，不能换编号。修改报告必须先重读契约，用新 resultId 和最新 expectedRevision；遇到版本冲突停止，说明已有其他报告，不自动覆盖。
6. 成功后用 {"command":"get-result","input":{"operationId":"{{OPERATION_ID}}","resultId":刚保存的resultId}} 读回，核对版本、候选数量及缺失项。向用户报告“结果已保存到插件操作记录，待采纳”，提供插件入口和原任务入口。工作台候选保存、正式达人档案更新、平台读取与浏览器自动化是否完成，必须分别按事实说明。

【附属来源观测】
已有合法取得的平台响应时，可调用 observation-contract，输入 {"operationId":"{{OPERATION_ID}}","taskId":原任务编号} 获取来源专用模板。按模板填写后，使用 preview-observation 预览，再以同一载荷调用 submit-observation 保存，最后 get-observations 按原操作、原任务和 observationId 读回。预览和保存支持唯一键封装 {"rawJson":"完整提交对象的原始 JSON 文本"}；直接保留原文，不先用 JavaScript 解析数值，以免长整数或小数被舍入。

Affiliate 来源编号与 Kalodata 来源编号保留各自命名空间；不得把昵称或来源编号自动当成统一达人身份。导入仅保存白名单字段投影，不保存原始响应；含敏感信息的原文件仍应由原资料保管者处理。原始浮点、金额范围、符号金额和未知费用不能冒充精确值，币种、时区、完整分页和费用真实性必须另行核验。离线观测不代表账号已登录、实时平台可读或已取得全量数据。观测不会自动变成报告字段，也不会自动写入业务候选。

【工作台待核验候选】
报告与观测交回不包含工作台采纳授权。用户明确要求保存该报告到工作台候选区后，才可经 prepare-adoption 展示绑定原任务、结果版本和观测集合的预览，并调用 adopt-result。保存结果未知时保留原 adoptionId，用 reconcile-adoption 只读核对；必要重试也只能使用原计划，不能换编号或载荷。只有供应端回执与候选读回一致，才可说明“已保存到工作台待核验候选区”。该状态不代表身份、费用、来源或覆盖已核验，不会改写旧达人档案或确认合作。工作台连接未启用时保留已保存报告和明确缺项，不启动或改造真实服务。

可将完整提交对象保存为 JSON 文件供用户在该任务卡片导入并预检，查看缺项后再保存报告；文件存入专属持久目录或按 MultiCC 文件存储规则保存，不能把仅存于临时工作区的文件说成已持久化。不要在结果中附带密码、令牌、代理认证或浏览器登录资料。
